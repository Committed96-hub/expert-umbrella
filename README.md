# НОВИК 24

Midnight-интерфейс городской платформы Новоуральска. React + TypeScript + Vite, Node.js API, SQLite для локального demo. Реальные платежи, медицинская запись и продажа лекарств отключены.

## Запуск

Требуются Node.js **24.x** и npm (используется `node:sqlite`).

```bash
npm ci
npm run dev
```

Запускаются API на 8787 и frontend на 5173. Открыть http://localhost:5173. API проксируется Vite на том же origin. При занятых портах остановите предыдущие серверы. `npm run dev:api` запускает API отдельно с наблюдением за файлами.

Production-проверка — два терминала:

```bash
npm run build
npm run dev:api
```

```bash
npm run preview -- --port 4180
```

`dist/` теперь **не является автономным приложением**: нужен API. На Vercel он обслуживается `api/gateway.ts` и rewrite `/api/*` в `vercel.json`; frontend и backend развёртываются вместе. Node.js 24 задаётся в `package.json`.

## Что работает

- Подтверждённые фотографии города, адаптер актуальной погоды и реальное время Урала, поиск, мобильная/desktop-навигация.
- Лента, объявления, мастера, магазины/акции, городские сервисы (расписания, адреса, медицинские demo-окна, кино, события), избранное и демопомощник.
- Биржа: demo-задачи, поиск/категории, серверное сохранение demo-отклика без отправки исполнителю.
- Услуги: выбор специалиста и demo-времени, серверная история demo-записей; медицинская запись по-прежнему недоступна.
- Кафе: два вымышленных кафе, меню, категории, поиск, доступность demo-позиций, добавление в корзину. Одна корзина — одно кафе.
- Корзина: количество, самовывоз/доставка demo, серверный расчёт цены и баллов, подтверждение demo-заказа, история. Никакой реальной оплаты или исполнения.
- Новик Бонус: 500 начальных demo-баллов, история начислений/списаний, начисление 5% за demo-покупку у партнёра, ограничение списания 20% стоимости блюд. Доставка исключена. 1 demo-балл = 1 ₽ в учебном расчёте.
- Аптеки: отдельный будущий модуль и контракт интеграции. Поиск объясняет отсутствие источника; цены/наличие препаратов не выдумываются. Покупка, бронирование и доставка отключены.

## Архитектура

```text
src/                       интерфейс, HTTP-клиент, пользовательские черновики
shared/                    DTO и контракты, без каталогов и секретов
api/gateway.ts             Web Request/Response entrypoint Vercel
server/handler.ts          HTTP-диспетчер, cookies, валидация origin и ошибок
server/service.ts          каталог, объявления, комментарии, расчёты, заказы, записи
server/database.ts         Database-контракт и локальный SQLite-адаптер
server/seed/               исключительно серверные demo-данные
server/adapters/           платёжный, аптечный, файловый и monetization seams
src/commerce/              Биржа, меню, корзина, записи и бонусы
src/pharmacy/              отдельный будущий аптечный интерфейс
src/components/CityProvider.tsx  контекст города и URL изображений из API
shared/commerce.ts         деньги в копейках, корзина, бонусный ledger,
                           PaymentProvider, StorageAdapter, PharmacyProvider
 database/schema.sql       подготовленная PostgreSQL-схема следующего этапа
```

Основные каталоги больше не импортируются в клиент: они загружаются из API и серверной БД. Корзина в localStorage содержит только ID и количество, избранное — ID. Цена, доступность и бонусы перепроверяются сервером. Старые локальные объявления/комментарии мигрируются в demo-API. API не принимает клиентскую итоговую цену; сервер вычисляет её по меню. Заказ и bonus ledger обновляются в одной транзакции; повтор с тем же idempotency key не создаёт второе списание, а изменение запроса под тем же ключом отклоняется.

## Хранение и ограничения demo

Локальная SQLite хранится в `.data/novik-demo.sqlite`, не коммитится. `NOVIK_DB_PATH` позволяет сменить путь. На Vercel SQLite находится **только в `/tmp` и временная**: данные могут сброситься при холодном старте, смене экземпляра или деплое. Это осознанно ограниченный demo-адаптер, не production-БД. Заказы, баллы, объявления и комментарии изолированы по HttpOnly demo-cookie; реальной авторизации нет.

Перед реальной эксплуатацией нужны постоянный PostgreSQL/Turso-адаптер, асинхронный серверный доступ к БД, аутентификация, ownership-проверки, модерация, ограничения запросов и резервное копирование. PostgreSQL-схема подготовлена, но не применена к облачному сервису. Клиентский API-контракт сохраняется при замене серверного хранения.

Фото берутся из проверенного серверного фотореестра через `/api/photos`; атрибуция и лицензии доступны в интерфейсе и PHOTO_SOURCES.md. Для неподтверждённых мест используется нейтральный фон. `StorageAdapter.createUpload` отключён до подключения объектного хранилища. Сгенерированные иллюстрации удалены.

## Финансы и интеграции

Все типы монетизации предусмотрены в модели и серверной конфигурации, **enabled=false**: комиссия Биржи, еды и записей, продвижение исполнителей/объявлений, бизнес-реклама, партнёрские продажи, Новик Бонус. Ставки 0, фактических комиссий нет. Платёжный адаптер возвращает `not_charged`; внешние финансовые API не вызываются.

Следующий этап:

| Возможность | Нужная интеграция |
| --- | --- |
| Погода | Разрешённый погодный API с серверным ключом, кешем и временем обновления |
| Биржа | Кабинеты заказчика/исполнителя, постоянная БД, уведомления, модерация, правила заказа |
| Записи | API партнёров и календарей; для медицины — официальный API учреждения/ФМБА |
| Кафе/еда | Согласованное меню/наличие, CRM/POS партнёров и доставка, статусы исполнения |
| Платежи | Серверный acquiring/SBP-провайдер, hosted checkout, подписанные webhooks, возвраты и reconciliation |
| Аптеки | Лицензированные местные партнёры и разрешённый API наличия/цен, правомерность каждого способа заказа/доставки |
| Бонусы | Постоянный ledger, правила партнёров, начисление после подтверждённой покупки, возвраты/отмена |
| Фото/файлы | S3/Vercel Blob, контролируемые signed upload/download URLs |
| Городская информация | Официальные фиды перевозчиков, справочники учреждений, кинотеатров и организаторов |

Секреты должны храниться только в серверном окружении. `.env.example` содержит имена будущих настроек без значений; не используйте `VITE_` для секретов. Демопомощник не подключён к LLM.

## Проверенные фотографии Новоуральска (Preview)

Фотореестр находится на сервере в `server/media/registry.ts`, контракт — `shared/photos.ts`, API — `GET /api/photos`. Компоненты `CityPhotos` показывают атрибуцию, ссылку на первоисточник и лицензию. Полный перечень и ограничения: [PHOTO_SOURCES.md](PHOTO_SOURCES.md). Генерированные городские иллюстрации удалены. Оригиналы не ретушируются и выводятся целиком, без растяжения; подмена неба не выполнялась. Для неподтверждённых объектов оставлены нейтральные фоны.

Есть дневная и ночная темы с сохранением выбора. Экраны работы, парков, камер и ТЦ доступны из навигации; они честно показывают, что интеграции не подключены. Торговые центры обозначены по названиям из задания, без вымышленных адресов и предложений. Существующие каталог, поиск, объявления, комментарии, Биржа, запись, меню, корзина, demo-заказ и бонусы сохранены.

Погода вынесена в отдельный серверный адаптер `server/adapters/weather.ts` и `GET /api/weather`: Open-Meteo, расчётная текущая температура и давление на поверхности (мм рт. ст.), отметка времени источника, таймаут, проверка свежести и кэш. При ошибке показывается отсутствие данных. Бесплатный endpoint предназначен для некоммерческой демонстрации; перед монетизацией требуется коммерческая лицензия/платный endpoint и серверная конфигурация провайдера. Источник и условия: https://open-meteo.com/en/terms, данные CC BY 4.0. В этой рабочей среде запрос к погоде недоступен; работу реального источника нужно подтвердить на Preview.

Дополнительные проверки:

```sh
CHROMIUM_PATH=/usr/bin/chromium BASE_URL=http://localhost:5173 npm run test:photos
CHROMIUM_PATH=/usr/bin/chromium BASE_URL=http://localhost:5173 QA_THEME=light node tests/accessibility.cjs
```

Тест фотографий намеренно блокирует внешние изображения и проверяет отказоустойчивость, а не успешность их загрузки. Для настоящей приёмки фото нужны разрешённые сетевые домены Wikimedia и визуальная проверка снимков. Далее предпочтительно перенести оригиналы в объектное хранилище с сохранением лицензии, авторства и контрольных сумм.

Эта версия публикуется из отдельной ветки `preview/verified-novouralsk-photos`; `main` и Production не изменяются.

## Реальный город и интерактивные демонстрации — этап 4

Реестр объектов и доказательств: `server/sources/real-city.ts`, контракт и интерфейс заменяемого источника `shared/real.ts`, API `GET /api/real-city`. В каждом объекте есть REAL/статус, ссылки, способ и дата проверки, дата сведений, условия использования и статус прав на фото. Фактические карточки отделены от учебных действий. Подробный перечень, источники и оставшиеся ограничения: [REAL_CITY_SOURCES.md](REAL_CITY_SOURCES.md).

Новые маршруты: `#cinema` и `#cars`. Реальные карточки доступны в существующих разделах. Для Solo есть отдельное учебное меню `#cafes/solo-demo`: цены и позиции DEMO, не официальное предложение ресторана.

API демонстраций: `GET /api/experiences`, `GET/POST /api/tickets`, `GET/POST /api/exchange-demo`, `POST /api/job-demo`. Места и цены билетов валидируются сервером; повтор выпуска с тем же ключом не создаёт новый билет. Статус заявки, чат, история билетов и черновик отклика изолированы по demo-сессии. SQLite остаётся серверным хранилищем; для PostgreSQL добавлены таблицы-модели, миграция внешней базы не запускается.


## Оформление фотографий и галерея

Маршрут `#photos` — шесть лицензированных исторических снимков Новоуральска. Фото не ретушируются: оформление создают рамка, тени, подписи и цветовые акценты интерфейса. Просмотр оригинала использует нативный `<dialog>` с закрытием по Escape и возвратом фокуса. Есть loading/error/retry фотореестра и повтор загрузки отдельного снимка. Новые источники и ограничения перечислены в [PHOTO_SOURCES.md](PHOTO_SOURCES.md).

```sh
CHROMIUM_PATH=/usr/bin/chromium BASE_URL=http://localhost:5173 npm run test:photo-gallery
```

Проверка загрузки/увеличения в этом тесте использует сетевую фикстуру, а не настоящий оригинал. Проверка реальных Wikimedia JPEG в среде ограничена сетевой политикой. Ветка публикации — `preview/photo-presentation`; Production остаётся прежним.
