# Новик 24

Первый MVP городской платформы для Новоуральска. Интерфейс на русском, самостоятельный дизайн, адаптивная сетка и нижняя мобильная навигация. Все жители, организации, события, цены и отзывы вымышлены.

## Запуск

Требуется Node.js 22+ и npm.

```bash
npm ci
npm run dev
```

Открыть http://localhost:5173. Для production:

```bash
npm run build
npm run preview
```

Сборка в `dist/`, предпросмотр http://localhost:4173. Можно разместить `dist/` на любом статическом хостинге. Навигация по hash не требует серверных правил маршрутизации.

```bash
npm test
```

## Что работает

- Городская лента: категории, подробности, реакции в рамках сессии, локальные комментарии.
- Услуги и мастера: поиск, фильтры, карточки, деморейтинги.
- Объявления: просмотр и создание с валидацией и сохранением в браузере.
- Магазины и акции: каталог, предложения и подробности.
- Городской поиск: поиск по всем разделам, несколько слов, избранное.
- Помощник: чат, подсказки, подборка по каталогу. Это локальная демонстрация, не подключённая языковая модель.
- Избранное, объявления и комментарии сохраняются в localStorage текущего браузера. При очистке данных браузера удаляются. Не синхронизируются между устройствами.
- Клавиатурная навигация, подписи элементов, закрытие модального окна по Escape, удержание фокуса в диалоге.

## Архитектура

- `src/data.ts`: типы разделов и сущностей, демоданные.
- `src/repository.ts`: интерфейс `CityRepository`, локальный адаптер, поисковая функция; интерфейс `AssistantGateway` и демореализация.
- `src/main.tsx`: интерфейс и состояние приложения.
- `src/style.css`: адаптивные стили и локальные иллюстрации без внешних ресурсов.
- `src/search.test.ts`: проверки поиска и корректного обозначения демопомощника.

Для подключения API заменить реализацию `CityRepository`, сохранив контракт. Для настоящего ИИ заменить `AssistantGateway` вызовом собственного сервера; API-ключи никогда не помещать в клиент. На следующем этапе стоит выделить экранные компоненты и добавить маршрутизацию для деталей сущностей.

## Следующий этап

1. PostgreSQL и серверный API: общие объявления, новости, бизнес-каталог; пагинация и полнотекстовый поиск.
2. Авторизация, роли жителя, бизнеса и модератора; проверка контактов; личные кабинеты.
3. Модерация и жалобы: состояния черновик / проверка / опубликовано / отклонено, журнал решений, защита от спама.
4. Карта, реальные адреса, геопоиск, избранное по аккаунту и уведомления с настройками подписок.
5. Настоящий ИИ на проверенных городских источниках, ссылки на источники и ограничение частоты запросов.

Сейчас нет реальной авторизации, отправки сообщений мастерам, сделок, карты или push-уведомлений. Нажатие на профиль и уведомления объясняет деморежим.

## Публикация на Vercel

В проект включён `vercel.json`: framework Vite, команда `npm run build`, каталог `dist`. В настройках Vercel выбрать Node.js 22 или 24. Серверные секреты для демоверсии не нужны.

При подключённом аккаунте CLI:

```bash
npx vercel login
npx vercel --prod
```

При первом запуске выбрать свой аккаунт/команду и создать проект `novik24`. CLI выдаст production URL после успешного развёртывания. Не передавайте токены через чат и не добавляйте их в репозиторий.

## Городские сервисы (версия 0.2)

В общем приложении появился раздел «Городские сервисы»: расписание транспорта, адреса учреждений, медицинские талоны, киносеансы и события. Все новые записи помечены **demo**; организации, адреса, маршруты, даты, цены и окна приёма вымышлены. Реальной записи к врачу, покупки билетов и регистрации на событие нет.

Прямые маршруты: `#city/schedule`, `#city/addresses`, `#city/medical`, `#city/cinema`, `#city/events`. `#search/saved` открывает избранное. Городские записи участвуют в общем поиске, избранном и подборке демопомощника.

`src/city/source.ts` задаёт нормализованную модель `CityEntry` с `source.mode`, названием источника, датой обновления, адресом, временем и доступностью. Контракт `CitySource.list(signal?)` поддерживает отмену. `createRepository(citySource)` позволяет внедрить реальный адаптер. `CityHub` не зависит от сетевого формата поставщика; адаптер преобразует официальный ответ в `CityEntry`. `CityDetails`, `Art` и `AssistantPanel` вынесены в отдельные компоненты, маршруты — в `src/routes.ts`.

### Источники для следующего этапа

| Раздел | Нужная разрешённая интеграция |
| --- | --- |
| Расписание | Официальный API перевозчика или опубликованный с разрешением GTFS/GTFS-RT-фид; лицензия и правила обновления |
| Адреса | Муниципальные открытые данные, официальный справочник учреждений или лицензированный геосервис для адресов/карты |
| Медицинские талоны | Официальная интеграция регистратуры обслуживающего Новоуральск учреждения/ФМБА; только разрешённые данные доступности, без персональных данных пациентов |
| Киносеансы | Официальный API/фид местного кинотеатра или разрешённая партнёрская интеграция билетного оператора |
| События | Официальные фиды учреждений культуры/организаторов (JSON/RSS/iCal), либо согласованный API афиши |

Эти API **не подключены**, их наличие и условия использования предстоит подтвердить у владельцев. Закрытые системы и страницы записи не скрейпятся. Для реального адаптера нужны лицензия/согласие на использование, серверный прокси для секретов, таймауты, кеш, проверка схемы, отметка свежести и отдельный статус недоступности. При сбое реального API нельзя выдавать demo за актуальные данные.

### Браузерная проверка

Команды, проверенные размеры экранов и ограничения проверки приведены в `VERIFICATION.md`. `npm run test:browser` запускает пользовательские сценарии, проверку загрузки/ошибки/повтора и аудит axe. Сначала запустите production preview на порту 4180; для установки браузера используйте `npx playwright install chromium`. При наличии системного Chromium задайте `CHROMIUM_PATH`.
