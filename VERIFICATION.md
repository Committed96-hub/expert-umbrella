# Проверка версии 0.2

12 октября 2026 года. Проверена production-сборка существующего репозитория.

- `npm run build`: TypeScript и Vite проходят, JS около 277 kB / 85 kB gzip; CSS около 19 kB / 5 kB gzip. Зависимости браузерных тестов не входят в клиентскую сборку.
- `npm test`: 6 успешных проверок поиска, маршрутов, demo-происхождения, отмены запроса, замены источника и демопомощника.
- Chromium, 1440×1000, 390×844, 320×740: все 11 маршрутов; карточки, категории, даты, доступность медицинских окон, глобальный и адресный поиск, пустые результаты и сброс, избранное после перезагрузки, создание объявления, комментарии и помощник проходят.
- Отдельная инъекция сбоя источника только в тестовом браузере: состояние загрузки, ошибка и успешный повторный запрос проходят.
- В этих сценариях нет JS-ошибок, HTTP-ошибок ресурсов и горизонтального переполнения; пустых/заглушечных ссылок нет.
- axe-core WCAG A/AA: 0 обнаруженных нарушений на пяти экранах (лента, медицина, события, поиск, помощник), на мобильном и desktop.
- Локальное появление карточек: примерно 0,26–0,42 секунды. Это локальная проверка, не измерение реальной сети, Lighthouse/Core Web Vitals или полный аудит доступности.
- Проверены скриншоты мобильного экрана. Safari/iOS и реальные устройства не проверялись.

## Повторение браузерных проверок

```bash
npm ci
npm run build
npx playwright install chromium
npm run preview -- --port 4180
```

В другом терминале:

```bash
npm run test:browser
QA_WIDTH=1440 node tests/accessibility.cjs
```

Для существующего системного Chromium: `CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`. Адрес сервера можно задать через `BASE_URL`.

## Источники и публикация

Все каталоги и городские сервисы используют demo-данные. Локальные объявления и комментарии создаются пользователем в браузере. Реальные медицинские записи и транзакции недоступны.

Vercel обнаружил два проекта, связанных с репозиторием, но запрос списка деплоев получил 403 (нет доступа к командной области). Собственной авторизации Vercel CLI в окружении нет. Статус нового production deployment не подтверждён; commit/push и статус GitHub фиксируются отдельно после отправки изменений.
